# Architecture — Studio Rack 0.2

## Native host and trusted interface

`src/platform/mac/Main.mm` owns the AppKit window, a non-persistent WKWebView for the bundled Studio Rack interface, the native image monitor, persistence and device commands. `assets/interface.html` is a local application resource, with no external scripts or network access. The native message handler accepts only the main frame of this bundled file. Navigation away from the interface is blocked; intentional Blackmagic support links open in the system browser.

The interface's bridge is not present in the browsers that render user URLs. Those are separate CEF off-screen instances with Chromium sandbox, TLS and origin protections active. No personal Chromium profile, screen capture, microphone, shell API or keychain secret is used. Each run has an exclusive temporary profile; the macOS mock-keychain backend prevents Chromium Safe Storage prompts. Temporary profiles are removed on clean exit.

The window has no title bar. Dragging unused background reports a drag intent to AppKit, which moves the window using pointer positions while the left mouse button is held. Interactive controls are excluded. The monitor is a native NSView above the WKWebView, positioned from the actual local monitor rectangle; no PNG/JPEG encoding is used in the rendering or SDI pipeline. The monitor is hidden while confirmation dialogs are open, so it cannot cover them.

AppKit and WebKit are system frameworks, with no third-party UI toolkit or redistributable browser dependency for the interface. CEF remains BSD/Chromium with bundled notices; the DeckLink SDK has its own EULA. The Windows host is not implemented; the composition/audio core, CEF client and interface asset can be reused with a Windows native host and a restricted interface bridge.

## Independent layers and composition

Each layer owns a CEF browser, an immutable latest BGRA frame and a bounded audio lane. CEF renders with transparent background and device scale 1; CSS opaque backgrounds remain opaque. `OnPaint` copies the frame before returning. Browser errors clear that layer's image and audio; other layers continue.

The scene worker waits for frame/configuration notifications rather than polling every 16 ms. Notifications coalesce; only visible sources subscribe, and unchanged frame pointers/configuration do not trigger composition. Weak wake signals and explicit unsubscription keep source publication safe after a Scene is destroyed. A configuration superseded during composition is discarded before publication.

For one visible source already matching the composition size, the immutable frame is reused directly. Other scenes blend from the bottom of the ordered stack to the top, using premultiplied source-over for all four channels. Scene configuration and source ownership are protected separately from the UI. Deleting a layer closes its browser asynchronously; retired runtimes remain owned until `OnBeforeClose`.

CEF's maximum windowless paint rate follows the selected mode (25/50 for the primary production modes, rounded to an integer and capped at 60 for other rates). This is a paint-rate request, not phase locking: fractional SDI timing remains rational, and external begin-frame scheduling/physical motion acceptance remain pending.

All layer browsers use the selected browser viewport. The composed viewport is fitted proportionally into the SDI target with transparent margins. Bilinear interpolation works on premultiplied channels. The native local monitor draws its checkerboard separately; that checkerboard never enters SDI. KEY shows the alpha mask locally. A static scene retains its last frame while scheduled SDI repeats it.

The development host permits at most 16 layers, independently of screen size. This is a resource guard, not a measured performance claim. The integration test uses two Full HD browser instances. Large stacks and UHD60 need measurement and optimization.

## SDI video and alpha

The backend enumerates real output devices, active-profile modes and both BGRA/ARGB support. Ordinary output and Keying support are queried independently: the HD Mini can accept RGB at 1080p50/59.94/60 for Keying even when the ordinary-RGB query rejects it. Exact rational frame durations are retained. Output is revalidated immediately before starting.

Three owned SDK frames are scheduled with `ScheduleVideoFrame`. Video callbacks return reusable slots to a bounded queue and count completions, late and dropped frames. A worker copies prepared SDR pixels and schedules the next frame; it skips past elapsed stream time after a serious delay instead of growing latency. Both output streams are enabled before any video is scheduled, following the SDK SignalGenerator order. Before queuing the programme, one transparent-black frame is displayed synchronously to prepare the physical output path; its count and SDK-call duration are reported separately from scheduled programme completions. This adds startup preparation only and reuses an existing slot; it does not enlarge steady-state queues. The first programme frame is scheduled one frame after stream zero (its programme index remains zero), with explicit initial audio silence lasting the same frame interval rounded up to one audio sample. Source PCM blocks cannot straddle that padding boundary, including partial writes. Subsequent queue sizes are unchanged; source-clock phase acquisition remains separate. The worker is waiting before preroll starts. PLAY begins only from the SDK audio preroll callback after the SDK reports the full audio target and all three video frames buffered; the wait for the preroll callback has a five-second deadline, after the preceding synchronous SDK setup calls. There is no manual RenderAudioSamples/EndAudioPreroll/start sequence. A timeout cleans up owned resources, including playback that started concurrently with the timeout. Telemetry records the actual queues at start and the first dropped scheduled video index (zero-based; absent if unknown). This readiness gate does not phase-lock CEF content or remove the residual A/V offset.

Scene publication also maintains a bounded temporal history. `OnPaint` is stamped on arrival in the shared 48 kHz uptime domain; this is **not decoded content PTS**. Resize preserves it and multi-layer composition uses the newest child stamp. Configuration revisions clear the history and establish a publication barrier. The local monitor still reads the latest immutable frame directly.

SDI selects the nearest available historical frame to `audioSourceOrigin + scheduledStreamTime`, allowing at most half an output frame ahead and favouring the past on ties. No renderer wait is introduced. The audio mapping is currently rate 1:1; future adaptive rate correction must update both destinations. Missing/wrong-size history produces transparent black and separate startup/steady counters. Static frames remain reusable. History is limited to 16 entries, a nominal 500 ms span (retaining a static predecessor), and 192 MiB raw / 384 MiB raw-plus-prepared during output. These are ceilings, not guaranteed temporal coverage at arbitrary resolutions.

SDR conversion runs on publication, outside the history mutex; START primes retained frames before playback. Prepared immutable BGRA/ARGB pixels are reused by the scheduling worker; fallback conversion is counted. STOP releases prepared caches and restores the raw budget. This exchanges bounded RAM for less deadline work; large stacks/UHD still need physical performance validation. macOS holds a scoped user-initiated, latency-critical process activity while SDI is active, including PAUSE, and requests user-interactive QoS for the video worker. STOP, errors and quit release the activity. This does not prevent forced sleep or establish App Nap as the cause of any historical failure.

CEF BGRA is premultiplied sRGB8. At the SDK boundary, RGB is unpremultiplied, decoded from sRGB and encoded with the SDR Rec.709 transfer function using a lookup table; alpha remains full-range coverage. Primaries coincide. SDK frame metadata declares Rec.709. SDI YCbCr conversion and physical levels are delegated to Desktop Video; waveform confirmation remains necessary. An 8-bit web source does not acquire real 10-bit precision from the SDI transport.

RGB8 is supported for progressive HD/UHD; interlaced/SD and exclusively YUV output devices are not implemented. The physical straight/premultiplied behavior after the device keyer must still be checked against the receiving switcher, using the test patches.

## Web audio and SDI embedding

`CefAudioHandler` requests planar float stereo at 48 kHz, 480 frames per packet. It copies packets into owned, per-layer queues with a maximum of 64 packets and approximately 500 ms of timestamp history. Old data is discarded. Missing audio produces silence. NaN/Inf samples are sanitized.

**CEF timestamp domain:** the pinned build delivers uptime millisecond timestamps despite the header describing Unix-epoch milliseconds. The client now preserves these raw timestamps. Capture, SDI, monitoring and meters share the macOS uptime domain through `mediaSampleTime()`; there is no per-layer first-arrival wall-clock offset. Sleep-inclusive/uptime observations detect suspension and stop/reset the timeline. `steady_clock` is used for durations/telemetry, not as the media timestamp epoch.

Packet positions follow a continuous sample counter within 1 ms timestamp quantisation. Duplicates/out-of-order packets are discarded without clearing good history; larger overlaps are trimmed and true gaps remain observable. History generations reject copies that raced a clear. Backward coarse corrections can read retained history. Silence before a stream's first sample is preroll padding, separate from missing expected data.

The mixer sums visible, unmuted layers, applying gain 0–2, then hard-limits the stereo result to signed 32-bit PCM. Master mute is available in Setup Advanced; layer mute/gain are in the layer drawer's Audio section. Hiding a layer mutes its audio. PAUSE mutes the full audio mix and makes video transparent, without stopping SDI. PLAY stopped releases audio and video output. No microphone or system-loopback capture is performed.

DeckLink audio uses 48 kHz, 32-bit integer stereo and timestamped scheduling. Device queue depth remains three video frames (30–250 ms); the source-age budget is separate, provisionally 60 ms on raw PTS. A host/queue phase acquisition waits for two queue depths of consumption and four stable observations before calibration, then crossfades the coarse correction over 5 ms. This is initial phase acquisition, not adaptive rate correction. Actual read age and stream/queue phase are exported alongside coverage and recovery counters. A queue underrun recovers with future scheduling lead and phase reacquisition. Driver/FIFO and receiver presentation delays still require physical A/V measurement.

The callback retains the output interface, is stopped/detached before release, and fatal API errors cause controlled shutdown. Cleanup only disables resources successfully enabled by this backend. Diagnostics distinguish captured/scheduled frames, missing coverage, pre-source padding, clock recoveries/API errors and hard-clipped samples. Monitoring remains a separate destination; its real-time buffer/rate redesign is pending.

This establishes a shared scheduling timeline. Same-device SDI loopback has exercised it at 1080p25/50, but final content A/V acceptance remains open: paint arrival is not a content timestamp, and source phase varies across starts. A known-PTS VP8/PCM Matroska control through the same CEF path also showed start-dependent residuals (audit §10.10). Diagnostic media/display timestamps are logged but do not yet identify the content PTS of each native paint. No fixed compensating offset is applied. This does not constitute independent external A/V sync measurement. Browser/OS/device latency and the receiver's processing require loopback/listening tests. Pause, visibility and mute changes take effect after already scheduled buffers drain.

## Persistence, first run and failure handling

The versioned `session.json` stores the stack, per-layer controls and output preferences atomically. Invalid JSON is backed up before recovery. Legacy `settings.txt` is imported on the first new-format run. Only a genuinely new configuration creates one visible test layer; a saved empty stack remains empty.

The first detected compatible device is selected and saved unless a valid stored/user selection remains in the detected list. No compatible device opens SETUP with driver installation/authorization guidance. Refresh does not change driver permissions or device profiles. Configuration changes stop short of altering external Blackmagic profile or driver settings.

Device/format configuration is locked during PLAY. Device loss is detected by SDK failure or two seconds without video completions, followed by controlled stop. Reconnection is manual through Refresh. Quit requires confirmation only while SDI output is active (including PAUSE), then waits for all CEF browser close notifications before terminating the message loop and calling `CefShutdown`.
